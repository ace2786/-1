# 律所办案辅助系统 · 5分钟项目讲解（企业微信版）

> 建议朗读节奏：每节 ≈ 45-60 秒，总计约 5 分钟。可直接复制发企微。

---

**【0:00 开场·一句话定位】**
老师好，我做的是「律所办案辅助系统」——一套完全离线、由本地大模型驱动的刑事案件卷宗分析平台。律师把起诉意见书、扫描卷宗、银行流水传进来，系统自动产出七类分析报告，每条结论都能点击跳回原文页码。全程数据不出本机，这正是银行、律所这类涉密行业的真实部署要求。

**【0:45 为什么做这个】**
刑辩律师拿到几百页卷宗，最痛的三件事：找证据要点、对时间矛盾、筛无关材料。人工要几天，而且容易漏。我的目标就是把"阅卷"变成十分钟的交互。

**【1:30 核心功能演示逻辑】**
以演示案件"张某某涉嫌非法吸收公众存款案"为例：
一、上传三份材料——起诉意见书、司法会计鉴定、还有一份故意混进去的物业催缴单；
二、点「全部分析」，深度模型依次生成：证据要点（自动区分书证/物证/言词证据）、案件时间线、矛盾排查、无效材料过滤、卷宗摘要、庭审思路、流水专项分析；
三、亮点是矛盾排查：嫌疑人供述2021年6月才开始吸存，但司法鉴定显示2021年3月就有资金入账——系统标红"高危矛盾"，点开可以分别溯源到两份不同卷宗的原文位置；那份物业催缴单则被正确识别为无关材料并给出排除理由。

**【2:45 AI助手与多智能体】**
每个页面右侧有锁定当前上下文的AI助手。问它"本案一共有多少处事实矛盾？"，它不是硬编码流程——ReAct循环让模型自主决定：先查已生成的分析结果，再检索原始卷宗交叉核验，最后汇总回答。每一步思考、每次工具调用都写入JSONL审计日志，执行轨迹在界面上完整可见。这是"可观测性"要求的答案。

**【3:45 架构与技术选型】**
系统是一个Python内核加三个薄壳：Web GUI（FastAPI+Jinja2服务端渲染，零构建）、CLI（lawfirm ask 一行提问）、MCP Server（任何外部智能体都能把它当工具箱接入）。模型层是双路由：qwen3:8b负责深度分析，qwen3:1.7b负责快速对话，设置页可视化管理。RAG用numpy内存向量库，embedding不可用时自动降级哈希向量——保证断网也不宕机。安全上默认只绑定本机回环地址，上传走白名单+SHA-256存证。

**【4:40 收尾·飞轮与展望】**
所有用户反馈和修正都会沉淀进案例库，作为后续分析的few-shot样本，系统越用越准——这就是数据飞轮。下一步计划接入更大参数模型和扫描件版面分析。我的讲解到这里，欢迎老师提问。
